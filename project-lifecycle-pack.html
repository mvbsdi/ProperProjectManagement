Project Lifecycle

Dashed purple blocks indicate agile reconciliation loops — impasses that must be resolved before the project advances. No stage may be skipped; gates are auditable.

1
Opportunity Qualification Pre-SOW

Opportunity is identified, tiered by archetype (Greenfield / Recontrol / Upgrade), and assessed for complexity risk class.

⚡ Software: 48h LOE estimate ⚡ Controls: 48h LOE estimate Sales / KAM Solution Architect
EXIT GATE: Archetype + risk class confirmed. Software & Controls LOE estimate on file. No LOE = no sales pursuit resource allocation.
Reconciliation Loop A — Feasibility Impasse
If Sales has promised capabilities outside known product bounds, SA + Software + Controls jointly define what is feasible before solution shaping proceeds. Sales must re-align with customer before advancing.
2
Solution Shaping Pre-SOW

SA leads technical discovery with the customer. Key functions, interfaces, integration points, and exclusions are defined. Hardware and software touch-points identified.

⚡ Software Lead: named & participates ⚡ Controls Lead: named & participates Solution Architect (lead) Sales / KAM
EXIT GATE: Technical Feasibility Sign-off — named Software Lead + Controls Lead sign. No signature = no SOW draft.
Reconciliation Loop B — Scope Inflation
If customer requirements expand during shaping beyond the LOE estimate, a revised estimate is produced and commercial alignment is required before SOW is drafted. Change is normal; undocumented change is not.
3
Commercial Commit — SOW Freeze Contract

SOW is drafted and reviewed. All scope assumptions, exclusions, interface dependencies, and change order process must be explicit. Software and Controls sign off on scope language.

⚡ Software: signs scope language ⚡ Controls: signs scope language Sales (commercial lead) PM (assigned at this point)
EXIT GATE: SOW signed internally by Software + Controls. Any scope impacting UI, integrations, reporting, commissioning tools, or PLC logic must have explicit sign-off. Unsigned = no contract execution.
4
Project Intake — T₀ Kick-off

Formal project kick-off. Single accountable PM and single accountable TPM are named. Mandatory handoff meeting within 5 business days of contract execution.

⚡ Software Lead: attends, accepts scope brief ⚡ Controls Lead: attends, accepts scope brief PM (single DRI) TPM (single DRI) SA KAM
EXIT GATE: Named PM + TPM pair on file. Intake checklist complete. No unnamed PM/TPM = project cannot start scheduling.
Reconciliation Loop C — Requirements Gap
If FSD/HI discovery surfaces scope not covered in the SOW, a Change Request is raised immediately. Scope is not absorbed silently. TPM owns the CR; PM owns the schedule impact; Sales owns the commercial conversation.
5
Discovery & Requirements Requirements

TPM drives FSD and HI document creation. SA validates field and customer reality. Software and Controls co-author their relevant sections. Requirements are traceable to SOW scope items.

⚡ Software: co-authors FSD software sections ⚡ Controls: co-authors HI / controls sections TPM (lead author) SA (field validation)
EXIT GATE: FSD + HI baselined, customer-approved, and signed by TPM + Software Lead + Controls Lead. No baseline = no build start.
6
Design & Build Planning Planning

Build plan, staffing plan, integration test strategy, and hardware delivery dependency map produced. Software and Controls capacity reserved by named people — not generic resource pools.

⚡ Software: named staff, sprint plan, integration test strategy ⚡ Controls: named staff, PLC dev plan TPM (software schedule owner) PM (master schedule)
EXIT GATE: Named staff plan approved by Software Engineering Manager. Hardware dependency map acknowledged. No named staff = no build start.
Reconciliation Loop D — Integration Conflict
If software-controls interface behaviors conflict during build (e.g. PLC signal mapping vs. software expectations), a joint resolution session is called within 48h. TPM arbitrates; PM assesses schedule impact.
7
Build & Integration Active Build

Iterative build with regular software-controls-hardware integration checkpoints. Customization change requests processed through formal CR process only.

⚡ Software: builds, demos, integration tests ⚡ Controls: PLC dev, interface tests TPM (dependency & CR owner) SA (config support) PM (timeline & hardware)
EXIT GATE: All FSD acceptance criteria met. Interface test matrix pass. Outstanding items documented in punch list with severity tags. No untested interfaces advance to site.
8
Site Readiness & Commissioning Commissioning

FAT/SAT entry checklist must pass before travel or site access is authorized. Software and Controls sign site readiness gate. On-site, SA leads configuration with Software and Controls on call.

⚡ Software: signs site readiness gate; on-call during commissioning ⚡ Controls: signs site readiness; leads PLC commissioning SA (on-site lead) PM (logistics & schedule)
EXIT GATE: FAT/SAT checklist passed. Software + Controls sign readiness. Customer sign-off on commissioning scope.
9
Go-Live & Hypercare Live

Go-live criteria met before cutover. Hypercare window active with Software and Controls on defined rota. Post-launch defects triaged with commercial impact tags — billable vs. warranty.

⚡ Software: hypercare rota, defect triage ⚡ Controls: hypercare rota PM (cutover owner) KAM / Customer Success
EXIT GATE: Go-live criteria checklist passed. Change backlog triaged. Hypercare rota named and communicated to customer.
10
Project Closeout & Retrospective Closed

Lessons learned captured. Estimate variance recorded by archetype. Customer satisfaction noted. Findings fed back to pre-SOW process and estimation models.

⚡ Software: estimate variance + lessons learned ⚡ Controls: estimate variance + lessons learned PMO (aggregate + report) TPM PM
EXIT GATE: Closeout report filed. Variance data entered in estimation database. Project formally closed in system.

Gate Checklists

🔍

Gate 1 — Technical Feasibility

Required before SOW is drafted

  • Named Software Lead assigned and available
  • Named Controls Lead assigned and available
  • Software LOE estimate on file (even if rough order of magnitude)
  • Controls LOE estimate on file
  • Key customer interfaces identified (WMS, ERP, third-party APIs)
  • Hardware dependency list reviewed by Software for interface assumptions
  • Any capabilities promised verbally by Sales confirmed as feasible
  • Open risks documented with severity (High / Med / Low)
  • Technical Feasibility doc signed by Software Lead + Controls Lead
📄

Gate 2 — SOW Internal Sign-off

Required before contract execution

  • Software Lead has reviewed and signed SOW scope language
  • Controls Lead has reviewed and signed SOW scope language
  • Assumptions and exclusions explicitly stated in SOW
  • Change order process defined in SOW
  • Hardware delivery dependencies called out (impacts software go-live date)
  • Integration points and third-party dependencies scoped
  • Commissioning and training scope defined
  • PM named (or named at contract execution)
🚀

Gate 3 — Project Intake

Required before any scheduling or resource allocation

  • Single PM named as DRI (one, not three)
  • Single TPM named as DRI
  • Kick-off meeting held within 5 business days of contract
  • SOW and Technical Feasibility doc distributed to all team
  • Archetype confirmed (Greenfield / Recontrol / Upgrade)
  • Initial project timeline skeleton in scheduling system
  • Hardware procurement initiated or confirmed
  • Customer primary contact(s) identified
  • Initial cadence meeting scheduled
📋

Gate 4 — FSD / HI Baseline

Required before build starts

  • FSD signed by TPM + Software Lead
  • HI signed by TPM + Controls Lead
  • All requirements traceable to SOW scope items
  • Customer has approved FSD/HI (or provided written exceptions)
  • Interface definitions complete (signals, protocols, data formats)
  • Screen/UI inventory complete with acceptance criteria
  • Reporting requirements documented
  • Open items list reviewed — no P1 open items remaining
🔧

Gate 5 — Site Readiness (FAT/SAT)

Required before travel or site access authorized

  • Software Lead signs site readiness checklist
  • Controls Lead signs site readiness checklist
  • All FSD acceptance criteria tested and documented
  • Interface test matrix completed and signed
  • Punch list generated with severity tags (P1/P2/P3)
  • No P1 defects outstanding
  • Site environment confirmed ready (network, hardware power, access)
  • Training plan confirmed
  • Rollback/contingency plan documented
✅

Gate 6 — Go-Live Authorization

Required before production cutover

  • Customer sign-off on go-live criteria
  • Hypercare rota published and communicated
  • No P1 defects in open state
  • Change backlog triaged — items tagged billable vs. warranty
  • Post-go-live support contacts confirmed
  • Escalation path documented (software → TPM → Eng. Manager)
  • Closeout meeting scheduled

Project Intake Checklist

Complete this checklist at T₀ (contract execution). The PM and TPM are jointly responsible for completion within 5 business days.

👥

People & Accountability

  • Single PM named — full name, email
  • Single TPM named — full name, email
  • Software Lead named — full name, capacity %
  • Controls Lead named — full name, capacity %
  • SA assigned and briefed
  • KAM / Customer Success owner identified
  • Customer primary technical contact identified
  • Customer primary commercial contact identified
📁

Documents & Scope

  • Signed SOW distributed to all team members
  • Technical Feasibility doc attached to project record
  • Archetype confirmed: Greenfield / Recontrol / Upgrade
  • Project folder created with standard structure
  • FSD/HI kickoff scheduled with TPM + SA + Software + Controls
  • Any verbal commitments made during sales process documented
  • Known risks from pre-SOW logged in risk register
🗓

Schedule & Resources

  • Target go-live date confirmed with customer
  • Hardware procurement lead time confirmed
  • Software capacity formally reserved in scheduling system
  • Controls capacity formally reserved in scheduling system
  • Hardware delivery milestones mapped to software dependency dates
  • Third-party / vendor lead times identified
  • Initial master schedule skeleton created in project management tool
  • Weekly cadence meeting scheduled (PM + TPM + Software + Controls)
🔗

Integrations & Interfaces

  • Third-party system list compiled (WMS, ERP, APIs, PLCs)
  • For each integration: owner, protocol, data format, point of contact
  • Customer IT contact identified for network/security coordination
  • Hardware-software interface assumptions documented
  • Any customer-provided components or data noted with delivery timeline

Non-Negotiable Operating Rules

Rule 1
No Technical Feasibility Gate = No SOW

Software and Controls must sign the Technical Feasibility document before any SOW is drafted. Sales does not own feasibility — engineering does.

Rule 2
No Named PM/TPM Pair = No Project Start

Every project has exactly one PM (delivery DRI) and one TPM (software scope DRI). Three PMs with the same title is zero accountable PMs.

Rule 3
No Software/Controls SOW Sign-off = No Contract

Any scope item touching software UI, integrations, reporting, or PLC logic requires written sign-off from the relevant lead before contract execution.

Rule 4
Post-SOW Scope = Formal Change Request

Any customization, new screen, new feature, or integration added after SOW freeze requires a CR with LOE, schedule impact, and commercial impact before a single hour of work begins.

Rule 5
No FSD/HI Baseline = No Build

Build does not start until FSD and HI are baselined, customer-approved, and signed by TPM + Software Lead + Controls Lead. Verbal requirements do not constitute scope.

Rule 6
No Site Readiness Sign-off = No Travel

No engineer travels to site until the FAT/SAT checklist is complete and signed. Showing up to site to "figure it out" is not commissioning — it is expensive failure.

Rule 7
Software Capacity Is Not On-Demand

Software engineers are not a utility. Capacity must be reserved by name in the scheduling system at project intake. Surprise projects absorb nothing — they create debt.

Rule 8
Verbal Commitments Are Scope Debt

Anything promised to a customer by Sales, KAM, or SA that is not in the SOW is uncontracted scope debt. It must be surfaced immediately, logged, and resolved via CR or SOW amendment.
